# Frontend (React + Vite)

Supabase Auth handles registration, sign-in, and browser sessions. The API server stores participant IDs, groups, expenses, and settlements.

Needs Node 20.19 or newer (Vite 8 requires it).

## Configuration

Copy `.env.example` to `.env.local`, then set:

- `VITE_API_BASE_URL` to the currently running backend API base URL (the groups endpoint uses the host root, without `/api`). If using a temporary Cloudflare quick tunnel, update this value whenever its URL changes.
- `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` to your Supabase project URL and publishable (or legacy anon) key.

Enable Email authentication in Supabase. Never put a service-role key in frontend configuration.

## Run

Start the API server separately, then from `frontend/` run:

```bash
npm install
npm run dev
```

Open the local URL printed by Vite (normally `http://localhost:5173`).

## Data flow

- Supabase Auth handles authentication only. The frontend sends the current Supabase access token as a bearer token on API requests.
- The API creates and stores group and participant IDs internally. The UI does not ask users to enter or select IDs; each listed participant is a separate person, even when names match.
- Group creation sends `POST /groups` with `{ "groupName": "...", "members": [{ "name": "..." }] }` and expects `{ "groupId": "...", "groupName": "...", "members": [{ "id": "...", "name": "..." }] }`.
- Submitting contributions sends `POST /groups/{groupId}/expenses` with `{ "total": 1000000, "description": "Party", "payments": [{ "memberId": "...", "amountPaid": 500000 }, { "memberId": "...", "amountPaid": 300000 }] }`. The group ID is in the URL, not the body. Naira amounts are converted to whole kobo before sending; the endpoint calculates and saves the expense and returns the settlement summary.
- Expense history is loaded from `GET /groups/{groupId}/expenses`. Each returned expense contains `expense_id`, `description`, `total`, `created_at`, `balances`, and `settlements`. The UI converts monetary fields from kobo to naira and displays the member balances and suggested transfers.
- Running balances and settlements use the API.
- The API must verify Supabase access tokens and associate records with the Supabase user ID. If it still expects its old custom login token, requests will fail with `401`.
- Group and participant IDs remain internal API references used to associate expenses and payments with the right records. They are generated by the API and are not shown to users.
- Money is sent as whole kobo and converted to naira for display.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Dev server |
| `npm run build` | Production build into `dist/` |
| `npm test` | Unit tests |
| `npm run mock-server` | Optional legacy mock server; not the configured API server |

If email confirmation is enabled in Supabase, users must confirm their email before signing in. Supabase Auth persists the browser session.
